健檢

它記得的事，比你以為的多

你寫的：自訂指令
  • 你打字打進去的，你知道裡面有什麼
  • 你隨時看得到、改得掉、刪得掉
  • 設定 → 個人化 → 自訂指令
它寫的：記憶
  • 你沒叫它記，它自己記下來的
  • 設定 → 個人化 → 管理記憶
你趕時間，前後講過兩三次「不要一直問，直接做」
它記下來：這位使用者討厭被問
三個月後你交代一件它其實沒搞懂的事，它不問了，照它猜的做，結果兩百個檔案全部改完，你才發現規則不對
記憶的好處和代價
  • 好處：不用每次重講你的習慣
  • 代價：它會越用越限縮 —— 把你這次沒說要的那些做法，先幫你砍掉了

它變笨了？先看你自己貼了幾張紙

📋
第一天，你貼在冰箱上「小寶三點一定要吃點心，不然晚餐前會餓到鬧。」
第 ① 層　你寫下來的，天天算數
📝
帶了兩週，保母自己記下來「他只肯吃冰淇淋，換成別的會整碗推掉。」
第 ② 層　她自己寫的筆記，你沒看過
🌡️
今天早上你出門前說「他有點發燒，今天不能吃冰的。」
第 ③ 層　只有今天算數
🍦 下午三點 —— 三條規矩同時生效，但湊不出一個做法
  • 給冰淇淋 → 撞到 ③，今天不能吃冰的
  • 換別的點心 → 他整碗推掉，等於沒吃 → 撞到 ①
  • 什麼都不給 → 直接撞到 ①，而且晚餐前會鬧
  • 三條沒辦法同時做到。她只能挑一條照做
結果你回家看到小寶在吃冰淇淋。保母沒有變笨，是因為三張紙她沒法同時滿足

健檢

三個動作，二十分鐘做完一次健檢

① 檢查對話方式 找一場你真的做完一件事的長對話，就在那場裡問 —— 證據都在那場
② 優化自訂指令 把 ① 產出的句子加進自訂指令，開一場新對話讓它檢查
③ 清掉記憶 記憶會記住你的偏好，但也容易越用越限縮，把創意鎖死。
設定 → 個人化 → 管理記憶（依個人偏好決定）
健檢你的個人化設定 ｜ 貼到一場新對話裡
以下是我目前在用的個人化設定（設定 → 個人化，英文叫 Custom Instructions），原文貼在最後面 如果你還沒設過，就先貼第一堂課那份基礎方案當起點，再照下面檢查 把它當成別人寫的東西來挑毛病，不要客氣，不要先誇獎 請逐條檢查，每一條給一個判定： 1. 互相矛盾 —— 說明和第幾條衝突，以及衝突時你實際上會聽哪一條 2. 沒辦法檢查 —— 像「要專業」「講重點」這種，我無法判斷你有沒有照做 3. 只適用某一次工作 —— 日期、某個檔名、某次的預算，這種應該當次再講 4. 每次都送但用不到 —— 佔了額度，卻沒有改變你的行為 輸出格式： A. 建議刪掉的：條文 + 一句理由 B. 建議改寫的：直接給我改寫後的句子，我要能複製貼回去 C. 建議補上的：我沒寫、但你經常必須自己猜的地方 最後回答我兩個問題： - 如果只能留五條，你會留哪五條？為什麼？ - 這份設定裡有沒有任何一條，會讓你在我沒發現的情況下少做事？
健檢你的問話習慣 ｜ 在做到一半的對話裡問
先暫停手上的事。回顧我們這一整場對話，回答我： 1. 我哪幾次的交代讓你必須用猜的？當時你猜了什麼？ 2. 我重複解釋了幾次同一件事？是哪一件？ 3. 你有沒有哪一次做完之後，我要求重做？原因是什麼？ 4. 如果我下次要做同一件事，有哪三句話是我一開始就該先講的？ 第 4 題請直接寫成可以貼進 Custom Instructions 的句子 每一句後面加一行「不寫會怎樣」 不要安慰我，我要的是可以改的地方
健檢的重點不是刪掉幾條，是找出它一直在猜的事

工具

版本維護（git ＝ 電玩的存檔點）

它不是給工程師用的，是給「會把東西改壞」的人用的 —— 也就是全部的人

指令白話你什麼時候需要它
git commit存檔，順便寫一句這次改了什麼每次驗收完，立刻做
git log看目前有哪些存檔點想退回去之前，先看看能退到哪一個
git restore讀檔：把還沒存檔的改動全部丟掉，回到上一個存檔點改壞了、而且不知道怎麼救
你不用自己裝、也不用自己打這些指令，你唯一要記住的是時機 —— 驗收完，就 commit

第一版需求描述 ｜ 會議記錄整理
我負責部門每週例會的會議記錄。整套流程有 6 個步驟，這次只處理其中一段。 1. 問題：開完會我手上是一份很亂的筆記，要自己重讀一遍、整理成通順的段落、挑出這次的決議、再列出每個人的待辦。而且筆記裡到處是簡稱（「小陳」「PJ 那案子」），組裡每個人寫的簡稱還不一樣，新人完全看不懂。 2. 我要的：一個網頁工具。我把筆記整段貼進去，它產出四個區塊： - 整理過的會議摘要 - 這次的決議清單 - 待辦表格（負責人／要做的事／期限），欄位順序固定 - 這次的新名詞清單：它看不懂、或猜不準的簡稱，一條一條列出來讓我確認 3. 重要需知： - 名詞庫由人維護。工具只能「提議」新增或修改，一律要我逐條按確認才寫進去 - 沒有明確點到名的待辦，負責人一律填「待確認」，不要自己指派 - 討論過但沒有拍板的事情，不要放進決議清單 - 不寄任何信、不連行事曆 4. 技術限制：名詞庫放在我們部門的 Google 試算表，工具用 Apps Script 讀寫，組裡每個人都看得到、也改得到。 不要另外架伺服器，不要用到任何需要申請或安裝的東西。 Why: 「小陳是誰」不是我一個人的事，這份對照表本來就該全組共用；而且我請假的時候別人也要跑得動。 5. 怎樣算完成：前三個區塊的內容，跟我上次手動整理的那份對得起來。判斷不了的要單獨列出來讓我確認，不要自己補。 新名詞要在我逐條按過確認之後，才會出現在試算表裡；我沒確認的，下次還要再問我一次。 先不要開始。請先用你自己的話說一次你理解的需求，並列出你打算產出的四個區塊各有哪些欄位。有不懂的先問我，不要猜。

進階

Skill 是知識，MCP 是權限，Agent 是人力

你請了一個工讀生。你會給她三種東西，剛好就是那三個常聽到的名詞

📋
你給她好幾份 SOP她不用背，需要的時候再去查
這叫 Skill ＝ 你給的是知識
🔑
你幫她開通網路硬碟不然她連資料放在哪裡都看不到，只能一直跟你要
這叫 MCP ＝ 你給的是權限
🙋
你請她做一份活動企劃她參考過去的資料以及新需求，設計新企劃
這叫 Agent ＝ 你給的是人力

--- name: meeting-notes description: 開完會要把亂記的筆記整理成會議摘要、決議清單和待辦表格時使用。 觸發字：會議記錄、例會、開完會、會議摘要、待辦、決議。 --- # 會議記錄整理 ## 需要的輸入 一份會議筆記或逐字稿，以及這場會議的日期與名稱。 人名、客戶名、還沒公開的數字要先換成代號再貼進來。 Why: 會議記錄裡幾乎一定有還沒對外的東西，貼出去收不回來。 ## 步驟 1. 先把筆記整理成通順的會議摘要。 2. 挑出這次的決議清單。討論過但沒有拍板的，不要放進來。 3. 產出待辦表格，欄位固定為：負責人 / 要做的事 / 期限。 會議上沒有明確點到名的，負責人一律填「待確認」。 Why: 自己指派的話，被指派的那個人不知道自己被指派了。 4. 三個區塊分開放，方便逐塊複製。 ## 不要做 - 不要寄任何信，只把內容放在畫面上讓我複製。 - 不要連行事曆自動建立提醒。 - 不要替我補上筆記裡沒有的結論。 ## 怎樣算完成 三個區塊的內容跟筆記對得起來，判斷不了的單獨列出來讓我確認，不要自己補。
驗收：它會不會自己想到要用

兩種叫出來的方式手動叫：ChatGPT 打 @meeting-notes；Codex 打 /skills 從清單選，或打 $meeting-notes。自動叫：它讀 description，判斷你這次講的話對不對得上。
